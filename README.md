# ComfyUI-RunGroup · 运行组开关

一个纯前端 ComfyUI 自定义节点：把工作流按分组框（Ctrl+G 创建）拆成多个"运行组"，
面板上点选一个组运行，其余组整组静音——类似编程语言里的 switch，
只是 switch 的 case 变成了画布上的分组框。

```
┌─ 组A：抽卡 ─────────────────────┐   ╔═ 运行组开关 ═══════════════╗
│ Loader → KSampler → VAE解码 ──┐ │   ║ runMode  单选运行 ▾        ║
└───────────────────────────────┼─┘   ║ ● 组A：抽卡 · 5节点   ▶运行 ║
┌─ 组B：高清放大 ────────────────┼───┐ ║ ○ 组B：高清放大 · 3节点 静音 ║
│      ┌────────────────────────┘   │ ╚════════════════════════════╝
│      └→ USDU → SaveB              │        点行切组 → 直接 Queue
└────────────────────────────────────┘
```

## 两种运行模式（节点上的 runMode 下拉）

**单选运行**：只有选中组执行，其余组静音。适合相互独立的组（如 两套不同底模的出图流程）。

**接力运行（含前置组）**：组按**画布从上到下**排序，选中组N = 组1..N 全部执行。
后组的输入直接连线前组的输出（如 高清组 ← 抽卡组的 VAE解码），依赖就是普通的
节点连线，不需要任何中转节点。两个关键机制：

- **执行缓存**：接力到组B时，组A 输入未变（种子已固定）则整段命中缓存零开销——
  放大的就是你抽中看好的那张。连续 Queue 第二次连组A的 Save 都不会重跑。
- **前置组终端自动静音**：组A 的 Save/Preview 等落盘节点（判定标准：没有对外
  输出链接）在跑组B时自动静音，不会重复存一遍抽卡图。

**接力模式的使用节奏**：组A 种子随机多抽几轮 → 看中某张后把种子控件切"固定值"
→ 点组B行 → Queue 出高清版。ComfyUI 重启会清缓存，接力第一轮会重算组A。

## 为什么不是旁路（Bypass）

- 旁路需要输入输出类型一致才能直通，链路类型一变就断——这正是本节点要消灭的痛点
- 本节点只用**静音**（mode=2）：前端 `graphToPrompt()` 在提交前把静音节点从 prompt
  里整段剔除，后端根本不知道这些节点存在，零执行开销、零类型问题

## 用法

1. 框选一组节点 → `Ctrl+G` 建组并命名（如「抽卡」「高清放大」）；要几组建几组
2. 双击画布搜「运行组开关」或 Add Node → utils 添加节点
3. 选好 runMode，点节点上的行 = 切换运行目标，然后正常 Queue
4. **再点一次已选中的行 = 全部组静音**（空闲态，此时 Queue 不会执行任何组）
5. 选中状态随 workflow 保存（节点 mode 本身会被序列化），重开工作流不丢。
   注意行显示的是真实状态：组内**任一**节点活跃该行就显示运行——手动
   Ctrl+B 只旁路了组里部分节点时，行仍会显示运行，属如实反映

**约束**：单选模式下每组必须自带输出节点（Save Image / Preview）——静音组的
输出链接会在提交时被清理，多组合用一个末端 Save 会报 `required_input_missing`。
共享的加载类节点（Loader、提示词等）放组外，它们不受切组影响。

## 推荐布局（抽卡 + 高清放大，接力模式）

- 画布从上到下：组「抽卡」在上，组「高清放大」在下
- 组外共享：模型 Loader、LLM 提示词节点（comfyui-ollama-prompt-encode，配 lock）
- 组「抽卡」：KSampler → VAE Decode → Save Image
- 组「高清放大」：Ultimate SD Upscale 的 `image` **直连**抽卡组的 VAE Decode
  输出（4x-UltraSharp，denoise 0.25~0.35，upscale_by 1.5~2）→ Save Image

抽到好图：固定种子 → 切组B → Queue。改参数重抽：切回组A，随便折腾，组B随时待命。

## 原理与实现要点

- 纯前端虚拟节点（`isVirtualNode = true`），无任何 Python 节点，零依赖
- mode 常量：`ALWAYS=0`，`NEVER（静音）=2`，`BYPASS=4`；本节点只使用 0 和 2
- 勾选状态不单独持久化——组员节点的 mode 就是权威状态（与 rgthree 同思路），
  面板监听 `graphChanged` + 每 1.5s 兜底轮询增量刷新行
- 手动 Ctrl+B/Ctrl+M 改过的组会如实显示，点任意一行即归一化

## 兼容性

- 与 rgthree-comfy 并存无冲突（本节点实现参考了其源码模式）
- 只服务根画布的分组；子图（subgraph）内的分组暂不枚举
- 已知生态问题：ComfyUI 设置里的新 Node 2.0 渲染模式与 rgthree 不兼容
  （会卡顿、渲染错乱），保持默认渲染即可

## 安装

```bash
git clone https://github.com/zhaoruizhe81-bot/ComfyUI-RunGroup.git ComfyUI/custom_nodes/ComfyUI-RunGroup
```

重启 ComfyUI，浏览器硬刷新（Ctrl+F5）。无法直连 GitHub 的机器：在本机下载后，
把整个目录（至少含 `__init__.py` 与 `js/rungroup.js`）拷进 `custom_nodes/` 即可。
